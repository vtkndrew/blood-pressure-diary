# Дневник давления и пульса

Приложение: https://vtkndrew.github.io/blood-pressure-diary/ · [Каталог](https://vtkndrew.github.io/).

Русский дневник для одного человека. Сеанс объединяет дату и время, несколько измерений и заметку. Давление обязательно, пульс можно не указывать. Черновик сохраняется автоматически, готовый сеанс — кнопкой «Сохранить». Есть редактирование, удаление с подтверждением, фильтры, графики и печатный отчёт.

## Расчёты и перенос

Среднее за период — среднее значений сеансов с одинаковым весом. Среднее сеанса — по его измерениям. Отсутствующий пульс не заменяется нулём. Промежуточные значения не округляются; отображение — один знак после запятой. Дневник не классифицирует давление и не даёт медицинских рекомендаций.

JSON экспортирует все сохранённые сеансы с ID и версией формата, без незавершённого черновика. Импорт сначала показывает новые, совпавшие и конфликтующие записи. Для каждого конфликта выбирается текущая или импортируемая версия; подтверждение применяет объединение одной транзакцией. Максимальный размер входного файла — 10 МБ. CSV содержит отдельные измерения выбранного периода, экранирует текст и защищает от формул. Печать / PDF открывает системный диалог с отчётом за выбранный период.

## Локальные данные и PWA

IndexedDB хранит сеансы и отдельный черновик без шифрования, аккаунтов, аналитики и межустройственной синхронизации. На сервер не отправляются записи или заметки. При ошибке записи введённое остаётся на экране; успешное сохранение не показывается. Устаревшее окно не может молча перезаписать данные другого окна. Перед загрузкой актуального состояния при конфликте скопируйте нужные значения из незаписанного черновика.

После сообщения «Готово к работе без интернета» доступен офлайн-запуск и ввод. На Android откройте раздел «Приложение» или меню браузера и выберите установку. На iPhone/iPad: Safari → Поделиться → На экран «Домой», оставьте открытие как веб-приложение включённым. Safari и установленная PWA могут иметь разные хранилища; переносите данные через JSON.

Обновление применяется только после подтверждения и завершения очереди сохранения. Сеансы и черновик сохраняются. Очистка данных браузера удаляет их; регулярно скачивайте JSON-копию. Запрос persistent storage снижает риск автоматического удаления, но не гарантирует сохранность. После аварийного закрытия восстанавливается последнее успешно записанное состояние.

Scope и кеши: `/blood-pressure-diary/`, `blood-pressure-diary-*`; база: `blood-pressure-diary:/blood-pressure-diary/`. Каталог не имеет service worker. Разные пути одного домена не являются границей безопасности; каждое приложение обязано не удалять чужие базы и кеши.

## Разработка и архитектура

Node.js 22.13+ в ветке 22 (также поддерживаются указанные в engines версии). `npm ci`, `npm run dev`. Локально `/`, production `/blood-pressure-diary/`. `npm run build`, затем `npm run preview`.

- `app` — запуск React/PWA и глобальные стили.
- `pages/diary` — компоновка и координация сценариев.
- `features/diary` — очередь сохранений, жизненный цикл, редактор.
- `features/pwa` — установка, офлайн-готовность и обновления.
- `entities/session` — модель, расчёты, валидация, IndexedDB, отображение сеансов и графиков.
- `shared` — нативный диалог и независимые утилиты.

Публичные API slices, CSS Modules, типизированные props. Сохранение и эффекты вынесены в hooks и хранилище. Документы согласованного продукта: `docs/requirements.md`, `docs/GLOSSARY.md`, `docs/adr/`.

Проверки: `npm run check:lockfile`, `npm run format:check`, `npm run lint`, `npm run lint:architecture`, `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run test:pwa`, `npm run build`. Форматирование: одинарные JS/TS-кавычки, двойные JSX, ширина 100, trailing comma, arrowParens always. ESLint включает порядок импортов, пустые строки, curly all, hooks и остальные согласованные правила. Для браузерных тестов локально нужен Chrome и `npx playwright install webkit`; CI устанавливает Chromium и WebKit. Только синтетические тестовые данные. Артефакты тестов исключены из Git, CI не загружает их публично.

GitHub Actions проверяет код, unit-, браузерные и PWA-тесты, затем публикует main через Pages. Дополнительный сервер не нужен.

## Ручная проверка на телефоне после публикации

1. Открыть приложение в Chrome Android / Safari iPhone, дождаться готовности офлайн и установить.
2. В установленном окне сохранить синтетический сеанс, начать второй и оставить черновик.
3. Свернуть, закрыть через список приложений, открыть снова: проверить запись и черновик.
4. Включить авиарежим, открыть приложение, сохранить новый сеанс, снова перезапустить.
5. Вернуть сеть; при доступном обновлении подтвердить его и проверить данные.
6. Скачать JSON, проверить перенос в другом браузере. Не использовать реальные записи для публичных отчётов о тестировании.

Автоматические Chromium/WebKit-проверки не заменяют проверку установки и жизненного цикла на настоящих Android/iPhone.
